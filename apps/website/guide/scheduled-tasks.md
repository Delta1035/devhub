# 定时任务

::: tip 版本要求
定时任务从 v1.11.0 起可用。
:::

定时任务让 DevHub 按计划触发已有的脚本或批量任务，不用手动点击运行按钮。在侧栏「定时」中新建：选择执行目标、时间规则和目标冲突策略，然后启用即可。

## 执行目标

- **单个项目脚本**：保存的是项目 ID 与脚本 ID，项目重命名或脚本重新扫描后仍然有效；删除目标后任务会执行失败并说明原因。
- **批量任务**：按任务当前保存的步骤执行。复用正在运行的脚本时不会重复启动。

## 时间规则

| 规则     | 设置                      | 说明                                             |
| -------- | ------------------------- | ------------------------------------------------ |
| 单次     | 日期时间                  | 到点执行一次，执行后不再触发                     |
| 每天     | `HH:mm`                   | 每天同一时间                                     |
| 每周     | 星期几（可多选）+ `HH:mm` | 按本地时间，周日对应 `0`                         |
| 固定间隔 | 分钟数（1 ～ 525600）     | 从启用时起每隔 N 分钟一次                        |
| Cron     | 5 段表达式                | 分、时、日、月、星期；支持 `*`、列表、范围与步长 |

所有规则都按这台电脑的本地时间计算。Cron 使用标准 5 段格式，不支持秒级字段；日和星期同时受限时按“两者都满足”处理。

修改规则或重新启用后会重新计算下次执行时间。删除或禁用任务不会再触发。

## 目标已在运行时

每个任务单独设置冲突策略：

- **跳过本次**（默认）：目标脚本或批量任务正在运行时记录一次跳过，不影响已有运行。
- **停止后重新执行**：先停止同一个目标，再启动一次新运行。如果脚本正被其他批量任务复用，停止会影响那个任务，界面会给出提示。

最近一次结果可能是「已启动」「已跳过」或「失败」，失败时附带原因；任务列表中可以查看下次执行时间。

## 运行边界

- 定时任务只在 DevHub 进程存活期间执行，不写入 Windows 任务计划程序、systemd 或手机后台服务。退出 DevHub 后到期的任务不会补跑：单次任务标记为跳过，周期任务移到下一个未来时间。
- 任务保存在 DevHub 自己的 `userData/schedules.json`，不写入项目目录，也不上传到代码仓库。
- 启用、编辑、删除任务只能在桌面上完成。远程客户端可以查看任务列表并「立即执行」，不能修改定义（ADR 0032）。
- 也可以对任务点「立即执行」，其冲突策略同样生效。

设计决策见 [ADR 0032](https://github.com/Delta1035/devhub/blob/main/docs/decisions/0032-scheduled-tasks.md)。
