# 0012 依赖审计报告

- 状态：已采纳
- 日期：2026-10-03

## 背景

质量检查通过并不代表依赖没有已知漏洞。目前开发工具链中的 `http-cache-semantics` 与 `braces` 各有一项 high 告警，上游尚无已发布修复。renderer 库放在 devDependencies，仅审计生产依赖会漏掉随 UI 打包的库。

## 决策

- CI 新增独立 Ubuntu 审计任务，对全部依赖执行 `pnpm audit --json`，在 job summary 中列出严重性、GHSA 与依赖路径，并上传原始响应。
- 当前采用报告模式：漏洞告警不阻断功能检查和打包；不忽略或豁免任何 GHSA。网络错误、超时、无效响应仍使任务失败，避免误报为审计通过。
- 不增加依赖，不自动运行 audit fix，不覆盖到尚未发布或未经上游确认的版本。
- 已知告警持续记录在进度文档；修复发布后先更新并验证，再评估是否启用 high / critical 阻断门槛。

## 备选与理由

- 立即以所有 high 告警阻断：当前无可用修复，会长期阻断与漏洞无关的开发。
- 忽略已知 GHSA 或只审计生产依赖：会隐藏告警，且遗漏 renderer 依赖。
