# 0007 设置

- 状态：已采纳
- 日期：2026-10-02

## 背景

默认 shell、编辑器路径（检测不到 IDEA 时）、停止等待时间、关闭窗口行为等都写死在代码里；终端字号只能用快捷键调。需要一个设置页。

## 决策

### 两类设置，两处存储

| 类别     | 内容                                               | 存储                                                                                      | 原因                                                 |
| -------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 核心设置 | 默认 shell、编辑器路径、停止等待时间、关闭窗口行为 | core 的 `userData/settings.json`（zod 校验），API `getSettings` / `updateSettings(patch)` | 决定 core 在本机做什么；将来远程客户端看到的是同一份 |
| 显示偏好 | 主题、终端字号、回滚行数、GPU 渲染                 | renderer 的 localStorage                                                                  | 只影响当前设备的显示；手机端会有自己的一套           |

- 修改立即生效，没有「保存」按钮：core 发出 `settings-updated` 事件，主进程据此更新关闭窗口行为；停止等待时间在每次停止时读取；默认 shell 通过把它排到 shell 列表首位实现（`shells/prefer-shell.ts`），「+」与下拉菜单自然跟随。
- 编辑器：配置了路径且文件仍存在时优先使用，否则回到自动检测；设置页显示实际会启动的路径及来源（自动 / 手动）。
- 「选择…」用新增的 ShellApi `pickFile`（原生文件对话框）。

### 安全

编辑器路径会让 DevHub 执行用户指定的程序：core 校验必须是存在的绝对路径文件。M4 远程 API 不开放修改这类设置（与 ADR 0005 不开放远程终端同理）。

## 备选与理由

- 全部放进 settings.json：手机端调字号会改掉电脑上的终端字号，不合理。
- 全部放 localStorage：core（停止等待、默认 shell）读不到，远程端也无法查看。
- 设置用弹窗：设置项多，页面更容易浏览与扩展。

## 补充（2026-10-02）：自定义 shell

- 设置页「自定义 shell」：名称、程序路径（原生文件选择）、参数（空格分隔，双引号包住含空格的参数，`splitArgs` / `joinArgs` 在 shared 中）。最多 10 个，整体编辑后保存。
- id 形如 `custom-xxxx`；`shellIdSchema` 由内置枚举扩展为「内置 | custom-*」，因此可设为默认 shell。
- 程序路径与编辑器路径同样校验（存在的绝对路径文件）；配置后被删除的程序不出现在列表中。
- 旧的 `settings.json` 没有这个字段，用默认值 `[]` 读取；而部分更新的 schema 单独声明该字段**不带默认值**——否则 `.partial()` 下默认值仍会生效，任何一次无关的设置修改都会清空自定义 shell（已有测试防止回归）。

## 已知限制

- 暂不支持开机自启动、快捷键自定义。
