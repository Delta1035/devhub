# 0015 持久化运行历史与日志

- 状态：已采纳
- 日期：2026-10-03

## 背景

原历史只在脚本退出时记录结果，DevHub 崩溃会丢失本次记录；终端输出只在内存，无法在重启后排查失败。用户要求完善历史、清理和日志，CLI 与手机端暂缓，桌面端作为 MVP 范围。

## 决策

- 启动脚本时保存 `running` 记录，并在确认启动前等待写入队列完成。退出时更新同一记录为 `finished`。交互式 shell 不记录。
- 下次启动将上次未结束的记录标为 `interrupted`，结束时间与退出码为 `null`，UI 显示异常中断、时长未知。这里表示 DevHub 管理会话中断，不断言进程已退出；遗留进程继续由原有机制检测、处理。
- `run-history.json` 沿用版本 1，旧记录没有 status 时默认为 finished，原有时间、命令与结果保留。每个脚本保留最近 20 次已结束记录，当前运行额外保留；中断恢复也执行数量限制。
- 日志保存到 `userData/history-logs/`，每次运行一个原子更新的 JSON 快照。文件名是 runId 的 SHA-256，外部 id 不直接参与路径拼接；输入与读取的数据用 zod 校验。
- 每次最多保存最近 512 KB 的 UTF-8 输出，截断时不切断中文或 emoji；保留原始 ANSI，查看时转为可选择、复制的纯文本，不执行终端控制序列或渲染 HTML。
- 日志有输出时每秒做一次检查点，退出与正常关闭时立即完成最后一次写入。崩溃前尚未保存的最后一部分可能丢失，查看中断记录时明确提示。旧记录或缺失/损坏的日志显示日志不可用。
- 清空单个脚本的历史只删除已结束记录及其日志，不停止或删除当前运行记录。移除项目清理所有相关历史与日志，并屏蔽该项目晚到的运行事件，防止记录重新出现。
- 数量淘汰、清空、项目移除同步删除对应日志；启动时清理未被元数据引用的受管日志与临时文件，不删除其他文件。移除项目之前遗留下来的旧历史也在启动时清理。
- 元数据与日志写入统一串行处理，历史变化处理完成后推送 `history-updated`，避免 UI 在记录写完前读取旧列表。新增 clearRunHistory / getRunHistoryOutput 走现有自动 IPC 映射。

## 验证与限制

测试覆盖兼容、异常中断、检查点、UTF-8 上限、隔离清理、淘汰和路径边界；真实应用 E2E 验证日志跨重启查看、截断提示、清空/移除项目及异常退出后的恢复。

不保存所有历史输出；每次仅保留上限内的日志，不保证断电前的最后一次写入已经同步到磁盘。不引入新依赖。
