# 0006 批量执行（分组）

- 状态：已采纳
- 日期：2026-10-02

## 背景

日常需要同时拉起多个项目的服务（如前端 + 后端 + mock），并且有先后依赖：后端就绪后前端才能启动。PRD 把它列为 M3「分组：一组脚本按顺序一起启动」。用户希望提前做。

## 决策

### 数据：DevHub 本地，可跨项目

- 一个批量任务 = 名称 + 执行方式（`parallel` / `serial`）+ 有序步骤；每步是「项目 + 脚本 + 继续条件」。同一任务可包含多个项目的脚本。
- 存在 `userData/groups.json`（与项目列表同样的 zod 校验 JSON 存储，见 ADR 0002），不写进任何项目目录：任务往往横跨多个仓库。
- 保存时校验项目存在；脚本在执行时才解析（构建文件会变化），找不到就让该步失败并说明原因。名称不可重复。

### 执行：core 中的 GroupRunner，复用 RunManager

- 并行：同时启动所有步骤。
- 串行：启动一步，等它的「继续条件」满足后再启动下一步：

| 条件           | 判断方式                                                               | 适用         |
| -------------- | ---------------------------------------------------------------------- | ------------ |
| 进程成功退出   | `run-updated` 中退出码为 0                                             | 安装、构建   |
| 输出中出现文字 | 输出快照 + 实时 `run-output`，去掉 ANSI 控制码后做子串匹配（跨块拼接） | 服务就绪日志 |
| 端口可连接     | 每 0.5 秒尝试 TCP 连接 127.0.0.1 与 ::1                                | 服务监听端口 |
| 等待 N 秒      | 定时                                                                   | 兜底         |

- 除「等待 N 秒」外都有超时（默认 120 秒）；进程在条件满足前退出也算失败（「进程成功退出」除外）。
- 某步失败：后续步骤不再启动，已启动的保持运行；状态与原因推送到 UI。
- 已在运行的脚本直接复用（不重复启动），并对它判断继续条件。
- 停止：取消等待中的序列，并停止任务中每个脚本的活动运行（各自杀整棵进程树）。启动中被停止的步骤，启动完成后立即停止。
- 进度通过新事件 `group-updated` 推送（只在内存中，不持久化）；DevHub 退出时先取消序列再停止所有运行。
- 条件判断（`groups/conditions.ts`）的事件订阅、运行状态、输出与端口检测都经参数注入，用假计时器单元测试；端口检测另有真实 socket 测试。

### UI

- 侧栏项目列表下的「批量」区：执行 / 停止全部 / 编辑；执行中或失败时展开每步状态与原因，点击步骤跳到对应项目。
- 编辑对话框：项目与脚本下拉（脚本来自该项目的探测结果）、执行方式、每步继续条件，步骤可排序、删除。表单与 core 使用同一个 zod schema 校验。

## 备选与理由

- 把任务写进 `.devhub.yaml`：只能描述单个项目，表达不了跨项目的组合；将来 M2 的项目内配置可以再提供「项目内分组」。
- 串行只支持「等待进程退出」：服务类脚本不会退出，无法使用。
- HTTP 健康检查：M3 的健康检查再做；端口可连接已覆盖大多数「服务起来了」的判断。

## 已知限制

- 「输出中出现文字」是普通子串匹配，不支持正则。
- 端口只检测本机回环地址。
- 任务执行状态不持久化，DevHub 重启后不显示上次结果。
